# Groundwire v0.2 Visibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship an Angular operator dashboard where a live run list, a D3 interlocking DAG, and an approval inbox let an engineer approve or reject a gated action.

**Architecture:** FastAPI gains CORS, agent listing, richer run payloads, and a run graph derived from audit events. The Angular app is a signal-box surface: left route strip, diagram field, levers on the red signal. Compose serves the dashboard behind nginx that proxies `/v1` to the API.

**Tech Stack:** Angular (standalone), D3, existing FastAPI/Temporal/Postgres.

**Spec:** `Groundwire_PRD.md` (v0.2 — Visibility: FR17–FR19) · `PRODUCT.md` · surface brief `dashboard`

## Global Constraints

- Visual world is the signal box (user-chosen pick); Approve/Reject are levers on the diagram, not a modal.
- No Keycloak, no metrics charts, no Slack/email.
- Status vocabulary unchanged.
- Apache 2.0; D3 not Highcharts.
- Live list via 2s polling (no Cloudflare Queues in v0.2).

## Review Focus

- Empty board teaches how to start a demo run, it does not say “nothing here.”
- Rejected runs show the tool node as skipped, never executed.
- Keyboard: filters, row selection, and Approve/Reject are reachable.
- Worker restart while inbox is open: the pending row remains until a decision.
- Mobile: route strip stacks above the diagram; levers stay usable.
